# 参赛演示与技术论证草稿

## 一句话定位

息刻是面向日常场景的健康素养工作台：帮助用户记录生活线索、核对健康说法的原始资料、留下小行动并回看变化。不提供诊断或治疗建议。

## 建议演示路径

1. 在首页切换大学生、职场人士或年长者画像，说明内容入口随场景变化；点击三步流程中的“记录”，编辑今日睡眠、活动和心情。
2. 从首页提问“熬夜后怎么安排睡眠？”，进入证据工作台。展示回答中的 `[S1]`、命中词、原始机构与日期，并打开原始资料。解释“相关资料”不等于用户说法已被证明。
3. 提问“明天的股票价格是多少？”展示资料不足时的拒答；提问“处方药可以自己加量吗？”展示转向医生或药师的边界。不要把急症问题当作娱乐演示。
4. 将一条适用的小行动加入列表、标记完成，再到 7/30 天回顾查看真实记录覆盖率和描述性变化。
5. 用虚构邮箱演示本机账号、首次画像填写及独立空白工作区。明确说明页面显示的验证码不发送邮件，不能证明邮箱归属。

## AI 技术方案

`KnowledgeCatalog` 保存人工整理的短摘要、来源机构、日期、原文条号与链接；检索返回匹配词与排序分数，最多两条。`AiService` 默认由 Mock 执行可重复的安全演示；用药、紧急、资料不足走明确分支。可选的 Chat Completions 适配器将问题和本次匹配的带编号摘要发送给模型，要求引用 `[S1]` 等编号；若输出缺少合法编号或模型异常，则回退 Mock。用户主动勾选后，相关问题才会携带近七天记录的描述性汇总。健康分类不进入模型请求。

已确认一台腾讯云 Lighthouse 香港三区实例（2 核、2GB、40GB SSD），计划以腾讯云 [TokenHub API](https://cloud.tencent.com/document/product/1823/130078) 作为真实模型联调目标，并依据[语言模型调用概览](https://cloud.tencent.com/document/product/1823/130079)选择已开通地域的接口。密钥只从后端环境变量读取；当前未接入真实密钥，不能宣称已完成真实模型评测。默认邮箱模式也只是本机验证码演示；可选 SMTP 通道尚未实际投递，不能宣称完成正式邮箱验证。

## 可展示的验证证据

- `frontend` 的格式检查、Lint、TypeScript 和 Vite 构建。
- `backend` 的 Maven 测试与打包；十条固定问题覆盖资料匹配、拒答、用药和紧急分流，并测试模型无引用或伪造引用时回退。
- 本机实际 API 流程：匿名画像、账号资料、记录读写、提问与行动。提交前还需录制桌面和窄屏的真实交互视频。
